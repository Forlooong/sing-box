# 已批准的实施顺序（2026-10-13）

目标是把各 VPS 的网站、证书、代理节点和私有订阅纳入同一个可恢复的管理入口，减少配置
漂移并保持旧客户端兼容。这里记录执行顺序和验收条件；共享数据结构在
[implementation-contract.md](implementation-contract.md)。

1. 建立隔离 Git 分支并固定依赖版本。保留 GPL 归属；不把原工作目录中的服务器密钥带入项目。
2. 建立结构化状态、独立凭证、稳定节点 ID、全局锁、文件事务与不可回退的令牌撤销记录。
3. 接通 REALITY/HY2、默认中性网站、Nginx TCP SNI 分流、本机 REALITY 目标和可信证书。
   TLS1.3/X25519 密钥交换/H2 必须验证；X25519 不是证书签名算法。
4. 接通唯一节点选择组、URI 导入、raw/YAML 输出、模板与手工元数据、兼容路径和域名别名。
5. 接通四来源规则快照，下载、校验、激活分离；15分钟检查新构建、保留last-good，客户端
   12小时更新头仅为提示。规则文件仍由客户端从固定 GitHub tag 获取。
6. 扩展有明确无损映射的协议。VMess QUIC 保留旧监听与raw能力，明确标注无法导出Mihomo；
   Direct 是服务端转发能力。不要把解析通过宣称为端到端网络已通过。
7. 实现既有233boy/Caddy及独立订阅服务迁移，保留旧核心、凭证、SNI和自签证书pin。
   未识别结构整体拒绝。新旧共存至明确退役，不承诺无连接中断。
8. 接通安装、证书申请与续期、版本更新、脚本帮助、故障恢复；用单元、CLI、实际Linux核心
   和隔离端到端测试验证，再提交可审查代码。

不包含网页管理、多租户、远程订阅抓取、自动防火墙/SSH变更或未经指定的生产服务器上线。
真实公网ACME与中国境内可直连性需要部署后的实际网络观测；DNS解析正确并不能证明后者。

实施状态：以上代码、文档及本地验证已完成。114 项单元测试、20 种真实核心配置检查和
REALITY/HY2/VMess HTTP/1 隔离流量验证通过；具体证据与环境验收边界见
[验证记录](validation.md)。后续已按用户指定部署测试服务器，完成实机与公网验收；订阅名称和帮助修复后单元回归为128项，见 [测试服务器验收](server-validation-2026-10-13.md)。其后[质询审查](grilling-review-2026-10-13.md)确认四项稳定性问题，进入以下稳定化阶段；未发布远程发行版本。

## 稳定化与逐步解耦

按用户批准顺序修复四项问题并建立故障回归，优先验收 Debian 12 amd64 的 REALITY/HY2
场景，再验证完整订阅的实际客户端与一小时持续运行。结果和限制集中记录于
[稳定性记录](stability-2026-10-13.md)。

仅订阅内容发布已从无关代理操作中分离，独立校验、激活与恢复订阅服务。
域名、监听、节点凭证、程序升级等变更保留完整校验。当前沿用统一项目；未来明确需要
支持多种外部代理部署时，再提取独立订阅项目与命令，并保留原上游 `sb` 入口。
