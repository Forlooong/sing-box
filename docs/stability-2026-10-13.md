# Debian 12 稳定性修复与验收

本轮针对更新中断恢复、订阅版本确认、证书同步隔离、默认第二个 REALITY 节点四项问题，
并将仅订阅内容的发布与代理服务操作分开。保持现有统一项目，在模块边界上逐步解耦；
尚不新增独立订阅项目或在同一主机安装第二套竞争的 `sb` 入口。

部署过程使用候选生成器、独立恢复入口和正式文件事务，运行时逐项与候选内容匹配。

等价主分支历史合并后，Python 3.11/3.12/3.13 回归及真实 Linux 核心/持续工具 fixture 的
[四项 CI 任务](https://github.com/Forlooong/sing-box/actions/runs/38420478197)全部通过。

证书副本不支持通用手工回滚，需修复受管 lineage 后同步；未完成事务仍能恢复。
较新的证书副本事务不会阻挡无文件交集的普通回滚，有交集时明确拒绝覆盖新证书。

## 持续客户端验证

工具见 [client-soak.md](client-soak.md)。使用完整公网订阅、两个持续 Mihomo 进程，
每 30 秒分别通过 REALITY/HY2 请求网站，刷新间隔设为 300 秒；刷新完成后重新计时，
并在下一个采样点执行，因此实际刷新时间会随处理耗时略向后移动。
同时观测服务器服务状态、PID、自动重启次数、内存和订阅 generation。
强制全局代理用于确认测量通路，因此不把成功请求解释为规则分流决策正确。

首次启动在规则集就绪阶段失败，未开始一小时计时；当次服务器监测 132.529 秒，
服务状态、PID 和自动重启次数均稳定。诊断确认 17 个规则中有一个初次下载超时，
未生成缓存；工具加入总预算 120 秒、单规则最多两次主动重试，仍要求全部规则实际加载。
公网短测验证两协议各两次请求、同 PID 刷新及最后存活检查通过，没有以缓存替换公网下载。

最终一小时观测于 2026-10-13 15:01 UTC 启动（北京时间当晚，结束时已为 10 月 14 日）。
客户端准备成功后单独计时，最终结果为 **通过**：

| 项目 | 实测结果 |
| --- | --- |
| 客户端测量时长 | 3600.05 秒，结束前再次核对两个进程存活及实际节点选择 |
| REALITY TCP/Vision | 120 次请求成功，0 次失败；核心 PID 始终相同 |
| HY2 | 120 次请求成功，0 次失败；核心 PID 始终相同 |
| 完整订阅刷新 | 同进程成功刷新 10 次，0 次失败；全部 17 个规则集已实际加载 |
| 服务端观测 | 3926.649 秒、132 次采样；三个服务一直 active/running，PID 未变，NRestarts 一直为 0 |
| 订阅版本 | 每个服务端样本均就绪，运行中 generation 与磁盘一致 |
| 最终状态 | `sb check` 通过，三个服务与三个定时器 active；身份未变、证书队列为空、未完成事务为 0 |

最终运行启动时 REALITY 规则加载使用了一次主动重试，随后全部就绪才进入测量窗口；
这不代表 GitHub 冷启动下载永不失败。实测内存范围、延迟统计和首次失败说明均保存在
[汇总证据](evidence/stability-2026-10-13.json)，原始脱敏记录为

[服务端 JSONL](evidence/server-soak-2026-10-13.jsonl)。汇总内记录原始文件 SHA-256。

## 当前适用范围

这些证据只支持指定 Debian 12 amd64、REALITY TCP/Vision 与 HY2 的验收。
Debian 13、Ubuntu 24.04、ARM64、客户端 GUI、真实旧 Caddy 部署迁移、
生产证书自然续期、多地区网络质量、长连接吞吐和多日运行尚未据本轮结果验收。

当前保持统一安装和节点管理有利于继续利用已实现的网站、SNI、证书与恢复流程。
仅订阅名称、模板、元数据、已有域名下的路径/别名、令牌和已启用规则的快照更新走订阅范围；
域名、端口、节点凭证、启用规则定时器和程序升级仍做完整校验。
未来需要支持多种外部代理部署时，再提取独立适配接口和命令，保留上游 `sb` 的所有权。
